## 1. 项目定位

- Whole-Hearted Car Service Ltd.（牙买加金斯敦，中国人运营）修车厂综合管理系统。
- 当前交付：mock-only 高保真交互原型（Next.js 14 + React 18 + TS + Tailwind + localStorage 状态机），给公司/董事长演示；正式系统由专业团队按原型重建。
- 要替代的现实：Lark 开单表（16,110 行真实数据）。
- 技术约定：单分支 main；dev 端口 3210；提交前必须 typecheck + test:collaboration；改页面行为必须全量 e2e。

## 2. 系统总原则

1. 系统负责记录、计算、关联、筛选、提醒、追踪；用户有最终决定权。
2. 默认不阻止业务：缺料、未验证只提醒，不设门槛。
3. 合理的硬规则必须硬：
   - 没有挂账资格却要挂账取车 → 绝对不允许（先开通资格再挂账）。
   - 没有姓名 → 不能开客户资料。
   - 没有手机号 → 不能开客户资料（可以先填号暂不 OTP，验证以后补）。
   - 手机号唯一、车牌唯一。
4. 每单必挂正式客户（无散客）；BO/IR 只建在车辆上。
5. 改任何东西都留痕（谁、何时、前后值、原因）；历史只增不改不删。
6. 发给客户的内容必须支持中英文两版，由前台选择发送哪一版，且可自由编辑（不强制采用 AI 文案）。

## 3. 角色与权限

- 原型阶段：以超级管理员视角先做；未来通过开设部分权限来区分岗位（8/17 定）。
- 权限设计参考 PRD 八角色矩阵（老板管理层/前台服务顾问/收银前台/维修工/维修组长/配件/LiJian 国际采购/超级管理员），财务岗位=收银前台不另设。
- 硬原则：没权限的接口不返回数据（fail-closed）；姓名/电话/VIN/金额是隐私；维修工不可见客户联系方式、成交价、收付款、成本、利润、工资、他组绩效；有权限即可看，页面不搞角色专属视图。

## 4. 单据模型（8/17 定稿）

- **业务单（BO）只有一种，工单就是 BO。** 建单方式：针对指定车辆新建业务单——前台自然语言大白话输入 → AI 拆成工时/配件双语收费项 → 人工可改 → 确认生成（8/16 定）。
- **检查结果（IR）是独立于业务单之外的另一种性质的数据，两者互不隶属。** 一辆车有多少检查结果和有多少业务单，没有直接关系。
- 报价单（Quotation）只用于跟客户磋商；客户同意了报价项目，前台**另外开业务单**，业务单不隶属于检查结果，不强制溯源链。
- **BO 里的一定是 Invoice**：发票只活在 BO 详情内，独立编号、版本、金额快照、付款状态 × 结算安排双轴。
- **IR 里的一定是 Quotation**：报价只活在 IR 详情内，独立版本 V1/V2/V3，客户逐项决定。
- 四种单据绝不混排；Quotation/Invoice 不占顶级导航。

## 5. 状态机

### 5.1 BO（业务单）
待派单 → 已派单（等维修工接车接单）→ 维修中（等回单）→ 回单待审核 → 已交单（完结）
- 停滞：接单后、交单前的旁路状态；维修工/前台都能标、都能恢复，全留痕。
- 回退一步 / 直接调整状态：必须填原因，进审计。
- 交单：前台核对绩效值（可改，记操作人）+ 施工班组（交单前随时可改派）；交单时间决定绩效归属月份；交单是绩效计入唯一触发点，只算一次。
- 取车不占 BO 状态，归停车费/交车模块。
- 里程不接车时登记：维修工接走后负责记录里程（每单开始前记录）；车辆详情显示最近一单 BO 的里程。

### 5.2 Invoice
未付款 / 未付清 / 已付清 ×（正常 / 挂账：未付款挂账 / 未付清挂账）。已付清完结；车开走不等于钱付清；欠账不把 BO 退回未完结。

### 5.3 IR（检查结果）
新建（前台录纸质单 / 维修工端回传）→ 审核并创建报价 → 发送客户 → 待客户回复 → 客户已回复（完结）。账龄 2 天黄、4 天红，持续催收，不闭环不下榜。
- 详情页（/orders/inspections/[id]，8/17 落地）：状态链 + 内部检查提交（原文/署名，内部证据）+ AI 整理草稿 + 已整理检查项目 + Quotation + 执行率 + 客户沟通记录（可新增，交付/回应分别留痕）；列表点击报告编号或“详情”进入。
- 状态链末两步由沟通记录推导：已发送且无任何回应 → 待客户回复；已发送且存在非“暂无回应”的回应 → 客户已回复。

### 5.4 车辆
在厂 / 不在厂 / 超时未取车。
- **闭环定义（8/17）：车还没离场，这辆车就还没闭环。** 不是没有业务单就闭环——维修工报告写不清楚、报价模糊客户无法理解，是车辆滞留的主要原因；车还在厂，责任就还在。
- 取车提醒条件：车辆在厂 + 相关 BO 都已交单（无下一步可执行 BO）→ 系统提醒前台执行通知取车（§9）。
- 在厂但从未建过 BO：显示在厂车辆没有业务单，请检查。

### 5.5 客户
有账单不等于有欠账。有账单 = 存在 Invoice（在途）；有欠账 = 存在未付款/未付清/挂账未清 Invoice（讨债对象）。所有未完结事项必须有人跟踪到完结。

## 6. 收费与金额

- 顶级分类：工时（labor）/ 配件（parts）/ 其他服务（other_service：停车超时、拖车、外派、其他）；折扣、减免、冲销、四舍五入是金额调整，不伪装成收费项目。
- 每个 Invoice 版本：工时+配件+其他+调整净额 = 总额（金额守恒）。
- 金额精确数值+币种 JMD；工资口径 CNY。
- 收款、付款分别汇总不合并；多币种分别汇总不混算。
- 单价 = 最终价，含 15% GCT，不再另算。
- 维修工回交缺项（里程/照片等）：填原因后仍可提交，不硬拦。

## 7. 编号、双语与打印

- 编号：BO `KGN-WH-2026080919422`；IR 带 -IR-；Quotation 带 -QT-（版本 V1/V2/V3）；Invoice 带 -INV-（版本另记）。KGN=门店码（曼德维尔分店换码）、WH=品牌、牙买加业务日、尾号服务端原子递增。
- 双语：客户姓名/车型中英双字段，中文主显示；表单输一侧自动翻译另一侧（音译规则）；AI 拆单时每条收费项目同时产出中英双语（人可改）。
- 打印：四联 A4（8/17 定案）：中文客户联 / 英文客户联 / 维修工联（不显示价格，带施工勾选+检查结果+签字栏，回交后前台代录）/ 中英参照联（留档）。
- 正式文件：真 PDF 生成（8/17 定案），中文/English/中英对照，同一份已批准数据生成，先预览后下载。已落地（8/18）：IR 详情页「正式文件 PDF」卡片，真 pdf-lib 生成（Noto Sans SC 中文字体子集嵌入），iframe 预览 + 下载（文件名带 ZH/EN/BI 后缀）；BO 四联暂保持浏览器打印形态。

## 8. 挂账（登记制 · 8/17 定案）

1. 客户级挂账资格：前台打开签名面板 → 找管理员现场签 → 前台提交 → 即时生效，无审批流；记录客户、签名笔迹、登记前台、时间；前台可撤销（填原因），撤销不删历史；重新开通需重新签名。
2. 逐 Invoice 签账：每张实际挂账的 Invoice 由客户针对单号/版本/余额/日期/语言签字确认。资格签名不能替代逐单签账。
3. 无挂账资格 → 不能挂账取车（硬规则）。

## 9. 停车费与取车通知（8/17 定案）

### 9.1 通知取车流程（前台手动执行）
1. 系统 AI 起草提醒文案，**永远产出中英两版**，内容包括但不限于：车辆状态、已完成的服务内容概述、未付账单金额、最迟取车日期。
2. 前台选择发哪一版（中文或英文），且文案可自由编辑，可以不采用 AI 起草的内容。
3. 通知渠道：Twilio 短信（发到客户 OTP 手机号）/ WhatsApp 链接 / Email（有邮箱才发）。
4. 这些通知动作是人工做的：**至少完成一项，前台说做了就是做了**，在系统里记录完成 → 开始记时（记通知完成时间 D）。不强制全部渠道都发。

### 9.2 计费日历
- D（通知完成日）→ D+1 宽限日（免费）→ D+2 起 JMD 2,500/自然日 → 取车日不计费 → 每 3 天提醒发停车费账单，直到登记取车。
- 后续提醒不重置首次通知日；门店临时不开门走减免，不改公式。
- 系统只提醒员工，绝不自动发消息给客户。

### 9.3 减免
全额免除 / 按整数天；保留原始天数金额+减免天数金额+原因+经办人+时间+（如需要）管理员签名+最终应付。同一案件累计减免 ≤ JMD 50,000 前台自行处理；> 50,000 管理员现场签名；禁止拆分多笔规避。

## 10. 绩效

- 员工携带指标 = 月标准工资 ÷ 提成比例（当前 25%）× 汇率（当前 23）。班组指标 = 全员之和。
- 完成率只算班组，不显示个人完成率/金额/排行；工资测算 = 标准工资 × 班组完成率（最低 0），只测算不记发放。
- 规则版本化：改比例/汇率新建版本+生效月份+四组影响预览；已锁定月份永不重算。
- 正式交单 → 记入交单月份班组绩效；未交单 = 待计入；已计入可更正（留原值）。
- 查看数据不签名（有权限即可看）；维修工在维修端查看才需签名确认。
- 历史对比只用已锁定完整月份；入职首月按天折算不乘完成率；月中离职按天折算后乘完成率。

## 11. 客户与车辆

- 客户必填：姓名 + 手机号（8/17 定：必须先填）；OTP 候补；驾驶证识别（姓名/生日/性别/地址，选填，无证不拦）；机构客户走主要联系人驾驶证（非强制）；公司地址与联系人地址分开。
- 客户详情：正式资料（含联系方式合并）、账单明细（每张 Invoice 欠多少红字）、当前/历史车辆、验证证据、备注（可随时编辑）；挂账资格双入口（开通/取消）；审计收修改历史小标签；无新建 BO/IR 入口。
- 车辆字段：车牌/车架号/发动机号/品牌/型号/年款/颜色/车身类型/座位/排量CC/燃油/里程——没有变速箱字段（8/17 定案）；不管登记到期（政府的事）。
- 车辆档案：车证照片 + 全部相关照片（维修故障照片入档案）、消费总额、历史 BO/IR/Invoice、当前客户、停车事实；车辆也显示自己的账单，但债务主体是客户。
- 一车一当前客户（允许暂不绑定）；换绑一次保存内结束旧关系+建新关系；历史关系永久保留。
- 车牌唯一（重复直接定位已有车）；手机号唯一。
- 无散客，每客户必建档；疑似重复只提醒，人工决定建新/返回/合并。

## 12. 维修工端流程（8/17 定案）

- 新单创建 → 派到某组 → 该组人员就能看到 → 到前台接车（实物交接后接单）。
- 接走后维修工负责：给车照相、记录里程、提交检查结果或工作报告，然后回单。
- 回单后前台审核（核对绩效值+施工班组），正式交单。
- 原型阶段维修工操作在前台端以身份切换模拟；独立维修工手机端未来另做（参考 2026-07-30 手机端设计规范）。
- 维修工不可见客户电话/地址/成交价/收付款/成本/利润/工资/他组绩效；不可改主状态/交单/收款。

## 13. 页面范围（8/17 定案）

**本轮优先做（业务相关）**：客户/车辆登记、开单（业务单+AI拆单）、检查结果与报价、客户沟通（含通知取车短信/WhatsApp/Email 流程）、维修工端流程、绩效结算、停车费、收付款与挂账。
**后置**：配件采购（需求大厅/本地/国际/物流）、任务系统（暂不做，业务做完再看要不要）。
**已实现模块**：工作台、客户、车辆、业务单（半成品待接线）、检查结果、停车费、收付款、绩效、营收。

## 14. 开发流程规范

1. 先方案后代码：动页面结构前先出静态示意/文字方案，老板点头再动手。
2. 老板说改哪就改哪，微调不做重排，不擅自扩大范围。
3. 有分歧要反驳并给专业建议，不无脑顺从；不无限抬杠。
4. 交付=能点开的页面+桌面/430px 截图+测试全绿；文档不算完成。
5. 提交前：typecheck + test:collaboration；改页面行为必须全量 e2e；离开前必须提交。
6. dev 服务用托管后台任务常驻 3210；同一 worktree 禁双 dev server；不动 .next.bak-*。

## 15.5 2026-08-18 老板 17 条反馈 · 落实记录（追加裁决）

- 建单先选车，客户自动带出（车→人）；车辆搜索按车牌/车型/车架号/车主。
- 工单详情可编辑：收费项目/自然语言原文/备注都能改，改动留痕（editHistory）；已交单不能直接改（当月先取消交单）。
- 派单界面：班组卡片 + 车间一组/二组一键轮换；**工程机械组派单必须落到具体维修工**（名单：陈少松/李军军/曹琪/邱启发，待老板更新正式名单），不选人不能确认，API 硬拦。
- 取消交单：仅当月；跨月发现问题 → 开**售后单**（修好不计绩效值）或**对冲单**（负绩效值扣回原单，计入原班组当月），两单都关联原工单（linkedOrderId）。
- 接车里程：维修工接车时记录（可留空后补），详情/打印显示记录人与时间。
- 备注：中文留档 + 英文客户联两栏（翻译人可改）。详情/列表/打印中英双名。
- 四联打印版式对齐参考 HTML：品牌头/公司信息条/三栏 meta（客户/车辆+VIN/打印日期+班组+里程）/客户问题描述/分类项目表/付款与退款明细/维修工联不显示价格并带完成勾选与双签字栏。
- 收付款工作区新增退款入口（上限 = 已收 − 已退）。
- **绩效值（8/18 老板修正）**：绩效值是独立计算值，**默认 = 工时合计，配件不算绩效**（原来误把配件计入，已修正代码与种子）。
- 退款升级（8/18 老板定）：退款必须写明退的是什么款（工时费/配件费）+ 具体项目 + 方式；**对冲对冲的是绩效值**：跨月已交单的**工时费退款 → 自动开对冲单（退多少对冲多少，即对冲对应工时绩效，负绩效计入本月）**；配件费退款不冲（配件不产生绩效）；当月已交单必须先取消交单才能退；每笔退款自动生成退款单（receiptNo），**退款单打印给客户签字 + 拍照回传留档（可选，不签不影响流程）**；四联打印的付款记录标明退款类别。
- 接车接单不带里程：接单=车进厂，里程接单后再补录（详情页补录按钮）。
- 停车费收款即开票：每个未结清案件都有收款按钮；收款同时生成停车费 Invoice（other_service·parking_overtime，含减免调整），发票页显示账单金额/已付/未付/余额/历次付款记录，可打印。
- 四联客户联 = 客户收费凭证：账单金额、已付、未付、余额、历次付款记录全在上面（zh/en 均含）；办公室联打印出来给客户签字后拍照回传保存（待做：签字照片回传）。
- IR 报价不记录客户逐项接受/拒绝：报价只做磋商（版本 V1/V2/V3）；客户是否同意以业务单 Invoice 客户签字为准。
- IR 创建入口：选车 → 自然语言回交检查结果 → AI 整理检查项目+报价草稿（工时报价、配件清单另报）→ 生成详情记录 → 前台人工发客户（A4/PDF 三语）。
- DeepSeek/Twilio/翻译/全局语言切换：待后续轮次（Twilio 老板暂缓，凭证以后给）。
