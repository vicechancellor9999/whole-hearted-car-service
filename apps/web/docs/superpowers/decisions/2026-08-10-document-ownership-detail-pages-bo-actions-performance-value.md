# 用户正式决策：单据归属、详情页面化、BO 功能集与单级绩效值（2026-08-10 11:12）

## 一、单据归属（定死）

1. **检查报告（IR）包含报价单（Quotation）**：报价只存在于检查报告内，无独立顶级入口。
2. **业务单（BO）包含发票（Invoice）**：发票只存在于业务单内，无独立顶级入口。

## 二、详情一律用独立页面，不用弹窗（定死）

- 客户、车辆、业务单、检查结果的详情**必须是独立路由页面**（如 /customers/[id]、/vehicles/[id]、/orders/business/[id]、/orders/inspections/[id]），禁止居中弹窗形式。
- 已执行：客户/车辆详情页 2026-08-10 完成（commit 4fa1f0b，E2E 27/27）。工单两个详情页待工单线按此执行。

## 三、交单、收款、打印必须在 BO（业务单）内实现（定死）

业务单详情页必须包含以下功能入口（演示版接 Mock，标 TODO(backend)）：

1. **正式交单**：交单确认前必须核对本单绩效值；交单后单据进入"已交单未取车"，绩效值计入负责班组当月完成值。交单后改组锁定（沿用既有规则）。
2. **收款**：在 BO 内记录收款、体现付款状态 × 结算安排双状态（未付/部分付/付清 × 正常/挂账/特殊协商）。
3. **打印**：打印入口在 BO 内（正式文件生成沿用"同一份已批准数据出多语 PDF"的既定方向）。

## 四、单级绩效值（补上被遗漏的机制，源自原始 HTML 原型）

1. **每张业务单有"整单绩效值"（JMD）**：系统按已确认项目计算默认值，允许手工调整（调整只改绩效值，不改执行或财务状态，必须留审计）。
2. **正式交单 = 绩效计入的唯一触发点**：未交单的工单绩效"待计入"，交单后"已计入"；绩效页汇总显示"已正式交单绩效值"（已计入 X 单 / 待计入 Y 单）。
3. **绩效只归班组，不显示个人金额**。
4. 月度锁定前需操作者显式确认"已核对正式交单、班组、绩效值及工资测算"。
5. 现状差距：当前实现只有月度聚合绩效，缺少单级绩效值字段与交单计入流转——这是必须补齐的缺口。
