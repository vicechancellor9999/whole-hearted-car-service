# 用户正式决策：技术路线 —— 只做 Mock 演示，不做真实后端（2026-08-10 08:02）

**决策人**：项目所有者（lijianfu），经 WorkBuddy 代为记录，即时生效。

## 决策内容

1. **本项目继续走 Mock 演示路线**：所有数据继续由 Mock API / 种子数据 / 内存持久化提供。
2. **禁止自行引入真实后端**：不接入真实数据库、不实现真实鉴权、不接短信/OSS/OCR 等真实外部服务。保持"第一版不处理"清单有效。
3. **真实后端将由人类程序员另行接手开发**。因此：
   - Mock API 的接口契约（路由、请求/响应结构、错误码、权限矩阵）必须保持文档化、稳定、可读，作为后端接手的规格说明；
   - 领域层与 Mock 层的边界保持清晰，确保未来可整体替换为真实实现而不改动前端；
   - 重大接口变更前需在 docs 中说明理由，避免给后端接手制造隐性债务。

## 影响范围

- Codex：继续按 TDD 完善领域逻辑、Mock API 与测试；不做任何真实持久化/真实服务接入。
- WorkBuddy：继续纯 UI 与本地演示交互；不新增对真实服务的依赖。

## 补充修订（2026-08-10 08:27，同决策人）

**"不接真实服务"不等于"不做这些功能"。** 鉴权登录、短信通知、OCR 识别（车牌/证件）、附件上传等外部服务相关功能，**前端界面和完整交互流程必须照常做出来**，要求：

1. 每个功能有真实可用的 UI：登录页、短信发送/记录界面、OCR 上传与识别结果展示等，流程完整可走通演示。
2. 背后统一接 Mock 实现（如固定验证码、模拟识别结果、假发送记录），并在代码中以清晰注释标记接缝（如 `TODO(backend): replace mock SMS provider`）。
3. Mock 实现的接口签名按真实服务的合理形态设计，未来替换为真实服务时前端零改动。
4. 禁止的仍然只是"接真的"：不申请真实 API Key、不接真实 SDK、不连真实服务地址。
