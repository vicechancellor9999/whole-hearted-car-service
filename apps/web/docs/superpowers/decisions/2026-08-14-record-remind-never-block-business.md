# 用户正式决策：资料缺失只记录提醒，身份唯一性不得冲突（2026-08-14）

**决策人**：项目所有者（lijianfu），即时生效。

## 决策内容

Whole Hearted 综合管理系统是业务事实记录、缺项提醒、后续跟进和审计留痕工具，不是审批引擎，也不是业务闸门。

1. 资料缺失、尚未验证、相似候选、已过期、存在风险或流程未完成时，系统必须允许员工继续创建、保存、更新或推进业务。
2. 系统如实保存当前状态，并显示清楚的 `待补`、`待验证`、`可能重复`、`已过期` 或 `异常提醒`，不得把普通资料完整度提醒变成不可绕过的按钮禁用或 API 硬拒绝。
3. 员工继续操作时，系统记录操作人、时间、缺失项和后续待办；不得伪造“已验证”“资料齐全”或“无风险”。
4. 手机号可以不填；一旦填写，规范化号码只能属于一个客户。比较范围包括所有客户的主要号码、备用号码和 WhatsApp。同一客户可以在自己的多个联系字段中复用同一个号码，但不得把该号码保存给另一个客户。
5. 车牌号一旦填写并规范化，只能属于一辆车，不得把同一车牌保存给第二辆车。
6. 姓名、Email、企业名称等相似候选只显示提醒，不能仅凭相似阻止建档。
7. OTP 未验证、驾驶证未上传、驾驶证四项未填完、企业联系人证据待补等情况均允许建档，状态如实留在验证缺口和提醒列表中。
8. 除上述手机号和车牌唯一性、身份权限、安全边界及不可解析的技术故障外，任何新规格、计划、实现、评审或测试都不得自行增加“不得创建”“不得继续”“必须审批后才能操作”等业务门禁。

## 与技术和安全边界的区别

本决策撤销的是业务条件硬门禁，不要求系统伪造或保存无法表达的数据。

- 身份认证、最小权限、会话隔离、敏感数据保护继续有效；
- 文件损坏、请求结构无法解析、存储写入失败等技术故障应明确报错并保留员工输入；
- 幂等和并发保护只防止一次操作被意外重复执行；最终保存仍须重新检查手机号和车牌唯一性，避免并发写入制造两个所有者；
- 数据校验应优先规范化、标记缺项和保存原始业务事实，不能把普通业务不完整伪装成技术错误。

## 产品表现

- 主要操作按钮不因业务资料缺失而永久禁用；点击后先显示缺项摘要，员工可选择继续保存；
- 手机号为空时允许保存；手机号或车牌与其他档案发生精确占用冲突时，显示现有档案并要求清空、修改或打开现有档案，不能制造第二个所有者；
- 页面顶部、列表、详情和待办区都能看见尚未完成的项目；
- 提醒必须提供下一步动作，例如补 OTP、补驾驶证、核对重复客户或更新过期资料；
- 补齐后更新状态并保留前后审计，不删除原缺项历史；
- 不新增主管审批、签字放行或其他用户没有要求的流程。

## 优先级

本决策是全项目业务交互的最高优先级规则。任何旧设计中把 OTP、KYC、驾驶证、资料完整度或风险当作硬阻断的规定，与本文冲突时均以本文为准；任何旧设计允许跨客户重复手机号或跨车辆重复车牌的规定同样失效。
