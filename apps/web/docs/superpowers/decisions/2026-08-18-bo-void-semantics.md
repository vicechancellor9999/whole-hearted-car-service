# 决定：BO（快速工单）作废的语义（2026-08-18 老板定）

## 一句话定义

**作废一张 BO = 这张单从系统里"不存在于任何计算口径"，但单据本身保留可见、留痕、可恢复。**
不是删除：列表仍能看到（置灰 + 已作废徽标），详情页有红色横幅与恢复按钮。

## 作废意味着什么（逐口径）

| 口径 | 作废后的行为 | 实现位置 |
| --- | --- | --- |
| 绩效汇总（已计入/待计入，按交单月归属） | 整单绩效值退出统计；对冲单为负绩效，一并退出 | summarizeQuickOrderPerformance（跳过 voidedAt ≠ null） |
| 工资测算 / 规则预览 | 走绩效汇总快照，随汇总自动剔除 | 绩效模块以汇总结果喂工资测算 |
| 财务（应收/已收/余额/退款） | 不计入收付款工作台合计、欠账、财务桶 | payments-workspace、debt.ts、workbench-state.ts |
| 客户档案（欠账/累计消费/账单数） | 不计入 | debt.ts |
| 工作台提醒（待派单/维修中/…/欠账/取车） | 不计入任何桶 | computeWorkbenchReminders |
| 停车费案件 / 待通知取车 | 不计入；取车通知按钮消失 | parking-workspace、vehicleHasOpenQuickOrders |
| 列表状态 chips 计数 | 不计入（"全部"仍含作废单，因为不删除） | business-orders-workspace |
| 派生单据（售后/对冲） | 作废原单时联动一并作废；恢复原单时联动恢复（以"关联单作废（原单 xx）"原因标记区分联动/独立作废） | applyMockQuickOrderAction void/restore |
| 取车/付完全款（完结三件事） | 随单无效；恢复后原样回来 | 数据在同一单据上 |
| 收款/退款/补签字/改内容/打印 | 全部禁用（API 层拦 + UI 隐藏）；恢复后解禁 | mock-quick-orders.ts 各守卫 + 详情页 |

## 作废的门槛（老板 2026-08-18 定的两级答案）

1. **权限：不设限**。谁都能作废（只要填原因），前台/维修工/财务同权。
2. **资金：设硬门槛（老板 8/18 修正口径）**。**有付款记录的不能作废**——钱已动过，只能走退款/对冲处理，不能一废了之。无付款记录的可作废（欠账随单核销）。
3. **信息透明（不拦但明示）**：作废弹窗动态提示——已交单则写明"绩效将从 X 月统计退出"；已完结则加"撤销完结事实"；跨月则加"该月份报表已出"。

## 不受作废影响的东西（有意为之）

- 收入统计页（mock-revenue）是静态演示流水，本来就不从 BO 推导。
- 绩效模块的"锁定快照/工资测算"是静态演示数（AUGUST_ACTUAL 硬编码），不从 BO 实时推导；作废通过绩效汇总卡体现。
- 派单轮换指针（一键轮换）只记录"点了按钮"这个事实，不回滚。
- 单据历史（statusHistory）只追加不删：作废/恢复都是追加记录。

## 恢复

恢复 = 撤销作废标记，全部口径原样重新参与计算；被联动作废的关联单按原因标记联动恢复。
