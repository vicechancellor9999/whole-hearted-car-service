# Whole Hearted 完整双语系统设计

状态：用户已确认产品边界，并授权 Codex 自行决定技术结构、数据迁移与验收方式；用户只验收实际成果

日期：2026-08-28

## 1. 目标

中文和 English 是同一套正式系统的两个完整界面。英语员工从登录开始，能够阅读页面、完成输入、理解状态和错误、执行正式业务并打印所需文件，全程不依赖中文界面。

## 2. 产品边界

- 系统拥有的登录、导航、页面标题、按钮、表单、弹窗、表格、筛选、状态、空状态、确认、成功、校验、错误、权限和辅助说明全部提供中文与英文。
- 客户姓名、公司名、车牌、VIN、品牌型号、业务编号和文件名等事实保持原样。
- 维修备注、客户留言和评论等人工业务原文永久保留。界面明确标记为原文，并可在不覆盖原文的前提下查看译文。
- 维修班组、岗位、收费单位、支付方式和收费项目等结构化业务资料读取双语字段；英文缺失时显示明确的 `Translation required` 状态，不以中文冒充英文。
- 当前界面语言不改变正式业务事实、金额、牙买加业务日期、权限、审计和编号。
- 正式单据独立选择中文或英文文件；界面语言不自动替换已冻结文件。

## 3. 本地化架构

- 语言代码固定为 `zh` 和 `en`。
- 采用稳定消息键和同构的中文、英文目录；组件不得把中文正文当作翻译键。
- `useI18n()` 提供 `t(key, variables)`、当前语言、Intl locale、日期/数字/金额格式化和领域标签解析。
- 消息变量使用具名占位符并在运行时拒绝缺失变量。中文与英文目录的键必须在类型检查和自动测试中完全一致。
- 客户端 Provider 只负责交互式页面语言；服务端和打印模块使用显式 locale，不读取浏览器全局状态。
- 不采用 DOM MutationObserver、页面复制、机器翻译系统控件或英文缺失时回退中文。

## 4. 账号偏好

- `staff_accounts.ui_language` 保存正式账号偏好，值只能为 `zh` 或 `en`，默认中文。
- 正式会话接口返回 `uiLanguage`；语言切换通过鉴权接口更新当前账号，并写审计事件。
- `wh_language_v1` 仅作首次绘制和断网缓存。正式会话载入后以账号偏好为准；成功保存后同步缓存。
- Mock 模式继续只保存在浏览器，不写正式数据库。
- 根节点同步 `lang="zh-CN"` 或 `lang="en-JM"`。

## 5. 服务端与错误

- 正式接口保留稳定 `code`，前端以 code 和参数生成当前语言错误；不得把后端中文消息直接当作英文 UI。
- 未知错误使用当前语言的安全通用文案，原始错误只进入受控日志。
- 领域枚举、状态和审计事件按稳定 code 翻译；数据库不保存展示文案作为状态真相。

## 6. 业务原文和译文

- 人工原文显示时使用正确 `lang` 标记，并明确标注 `Original text` / `原文`。
- 可翻译字段的译文作为独立、可追溯内容保存或按需生成；不得覆盖原文，也不得被审计为原事实。
- 没有可用译文时英文界面显示 `Translation not available`，仍允许员工查看原文。

## 7. 可达页面范围

完整范围包括登录、经营概览、业务工作台、Business Order 列表与详情四个标签、Inspection Report、收付款与交车、停车费、客户、车辆、员工、基础字典、绩效、收入、系统设置、账号设置、提及、所有可达占位页面，以及它们的新增、编辑、删除、上传、收退款、打印和错误流程。

正式 A4、Receipt、退款签收单和停车单据继续使用各自已批准的文件语言合同。

## 8. 验收

- 中文和英文目录键集合完全一致；任何缺失键使测试失败。
- English 模式逐个打开所有可达路由，系统拥有的可见文案、ARIA 名称、placeholder、title、toast、dialog 和错误中不得出现中文字符。
- 允许出现中文的节点必须显式标记 `data-user-content` 或对应业务原文语义；自动审计不豁免普通容器。
- 至少完成一条 English 正式业务路径：登录、查找客户与车辆、打开 Business Order、登记业务操作、查看状态与打印入口。
- 语言切换刷新后保持，另一个浏览器会话重新登录同一账号后仍使用账号偏好。
- 全量前端测试、正式后端测试、类型检查、lint、生产构建和浏览器控制台检查全部通过。
