# Whole Hearted 平衡双主题设计

状态：用户已确认视觉方向与主题切换规则  
日期：2026-08-28  
时区：America/Jamaica

## 1. 目标

Whole Hearted 综合管理系统采用一套统一的平衡双主题。柔和亮色降低大面积纯白带来的眩光，舒适暗色使用中深灰表面和清晰的逐层提亮关系。所有应用页面、表格、卡片、弹窗、表单和状态组件通过相同的语义角色取色，在两种主题下保持一致的信息层级。

本轮只改变视觉主题、主题设置和颜色实现，不改变页面结构、业务功能、接口、权限、数据及正式业务规则。

## 2. 设计依据

- 采用 IBM Carbon 的分层原则：背景、一级表面、二级表面和嵌套表面按固定顺序叠加；亮色通过灰白交替建立层级，暗色通过逐级变亮建立层级。
- 采用 GitHub Primer 的语义 Token 原则：组件使用背景、文字、边框、交互和状态角色，不直接依赖基础色阶。
- 保留 Whole Hearted 蓝作为主要操作、选中、链接和焦点颜色；成功、警告和危险色只表达业务状态。
- 信息密度、现有字体、圆角、布局和操作位置保持当前产品风格。

## 3. 主题模式

系统设置提供三个明确选项：

1. `跟随系统`：根据操作系统 `prefers-color-scheme` 实时选择柔和亮色或舒适暗色；系统主题改变时页面同步更新。
2. `柔和亮色`：固定使用亮色主题。
3. `舒适暗色`：固定使用暗色主题。

默认值为 `跟随系统`。用户选择保存到浏览器本地设置，并在同源标签页之间同步。页面初次加载时在首屏绘制前确定有效主题，避免亮暗闪烁。

存储内容区分“用户模式”和“当前解析结果”：

- `wh_theme_mode`：`system | light | dark`；
- `wh_theme`：兼容现有代码的当前解析结果 `light | dark`。

旧的主题设置迁移为对应的明确模式；没有旧设置时使用 `system`。

|---|---:|---|

| `surface-2` | `#EDF1F5` | 嵌套区、表头、输入区 |
| `surface-3` | `#E4EAF0` | 选中前背景、悬停和更深嵌套 |
| `border-subtle` | `#D4DBE4` | 常规边框和分隔线 |
| `border-strong` | `#AEB9C7` | 输入焦点前边框、强调分隔 |

### 4.3 状态颜色

成功、警告、危险和信息分别提供 `subtle background`、`border`、`text`、`solid background` 与 `on-solid` 角色。状态卡在暗色主题中使用低饱和深色背景和高可读文字，亮色主题使用柔和浅色背景。金额、警告和删除操作不得只依靠颜色表达，还须保留文本或图标含义。

## 5. 组件规则

- 页面、应用外壳、卡片、表格、输入框、弹窗和菜单按 `background → surface-1 → surface-2 → surface-3` 顺序使用表面层级。
- 每个嵌套层只提升一级，不跨级跳色；同层组件使用边框和间距区分。
- 主文字、辅助文字、边框、焦点、悬停、选中、禁用和遮罩均使用语义 Token。
- 主色只用于主要操作、链接、当前选中项和焦点，不作为大面积卡片填充。
- 暗色主题不使用接近黑色的主内容画布；亮色主题不使用纯白作为大面积页面画布。
- 阴影保持轻量。暗色主题优先使用表面差和细边线建立层级。
- 正式打印件、Receipt、退款签收单和三联单使用独立文档配色：白纸、深色文字和适合打印的边框。页面内预览与系统打印保持一致。

## 6. 实施范围

### 6.1 主题基础

- 扩展全局 CSS 变量为完整的背景、表面、文字、边框、交互和状态 Token。
- 主题 Provider 支持三档模式、系统变化监听、本地持久化、跨标签同步和首屏无闪烁。
- Tailwind 语义颜色映射到 CSS Token；应用组件通过语义类取色。

### 6.2 组件迁移

- 应用外壳：桌面侧边栏、移动导航、主内容画布和身份区。
- 共用组件：页面标题、按钮、输入框、下拉框、弹窗、状态徽标、表格、卡片、加载骨架和滚动条。
- 业务核心：经营概览、业务工作台、Business Order 四个工作区、客户与车辆、员工、绩效、收付款、停车费和系统设置。
- 文档界面：业务单预览、Receipt、退款签收单和三联打印。

组件迁移完成后，业务页面不再维护独立的主题色表；页面差异通过布局和业务状态表达。

## 7. 可访问性与交互

- 普通文字与背景对比度至少达到 WCAG AA `4.5:1`；大号文字和关键 UI 边界至少达到 `3:1`。
- 键盘焦点在两种主题中清晰可见；焦点不能只用轻微背景变化表达。
- 悬停、按下、选中、禁用、错误和加载状态在两种主题中均可辨认。
- 尊重 `prefers-reduced-motion`；主题切换使用短暂颜色过渡，不产生大面积闪烁。

## 8. 验收

### 8.1 自动验收

- 主题解析测试覆盖 `system`、`light`、`dark`、系统主题变化、旧设置迁移及跨标签同步。
- 视觉 Token 测试验证两种主题的背景、三级表面、文字、边框和状态色均来自语义变量。
- E2E 覆盖主题切换、刷新持久化、首屏主题、Business Order 四个工作区、弹窗、表格和打印预览。
- 类型检查、定向 lint、相关单元测试和生产构建通过。

### 8.2 浏览器验收

在 1700×1114 桌面和 430px 窄屏分别检查柔和亮色与舒适暗色：

- 侧边栏、页面画布、主卡片和嵌套区能立即辨认层级；
- 业务单收费表格、维修轮次、金额卡、历史、评论、单据预览和操作浮窗文字清楚；
- 客户、车辆、员工、绩效、收付款和设置页无突兀纯白块、近黑块或主题混用；
- 成功、警告、危险和禁用状态含义明确；
- 打印预览保持白纸效果，系统打印内容清晰；
- 浏览器控制台无新增错误，现有业务操作和数据结果不变。
