# Whole Hearted 3210 单体应用设计

状态：用户已批准方向，并授权 Codex 自行决定实施、数据保护与技术验收细节

日期：2026-08-27
时区：America/Jamaica

## 1. 目标

当前 `http://localhost:3210` 的页面、菜单、打印样式和操作方式就是正式产品界面。合并后的系统继续使用这套界面，并在同一个 Next.js 应用进程内完成登录、权限、正式 API、PostgreSQL 读写、附件和打印。

开发候选版本使用 `http://127.0.0.1:3220`。现有 3210 运行版本和已验证安全备份保持不变，候选版本通过全部验收后再决定是否切换到 3210。

## 2. 实现选择

以 `apps/web` 为唯一 Web 应用源码，并将它从 Next.js 14 / React 18 升级到仓库已使用的 Next.js 16.3.2 / React 19.2.8。现有 3210 页面和组件留在原位置，正式服务、数据库、会话与权限代码作为同仓库服务端模块被该应用直接调用。

正式服务端模块使用独立别名 `@formal/*`。该别名在正式模块自身和 3210 应用中都指向仓库根目录 `src/*`，避免与 3210 前端的 `@/*` 别名冲突。服务端模块不得被客户端组件导入。

现有 `/api/formal/*` URL 继续作为界面兼容接口，但每个 Route Handler 直接调用同进程的正式 handler/service，不再发起 localhost HTTP 请求。这样可保留现有页面调用合同，同时消除第二个 Next.js 服务和额外网络往返。

## 3. 运行链路

```text
浏览器
  -> 单一 Next.js 16 应用（候选 3220，批准后 3210）
       -> 现有 PC 页面与打印页面
       -> /api/formal/* 兼容 Route Handler
       -> 正式会话、权限与领域服务
       -> PostgreSQL 与持久附件目录
```

PostgreSQL 是独立数据服务，不计作第二个 Web 应用。运行期间只能存在一个对用户提供页面/API 的 Next.js 进程。

## 4. 认证与权限

- 保持 `wh_session` HttpOnly Cookie、正式账号、数据库会话、服务端角色与委派权限。
- 登录接口在同进程完成认证，成功后继续跳转到 `/`；失败信息和限流行为保持现状。
- 页面入口可用轻量 Proxy 做登录跳转，但每个正式 Route Handler 仍独立校验会话与权限。
- 浏览器本地存储只保留界面偏好，不作为正式身份、权限或业务数据来源。
- 维修工 PC 限制、老板只读和敏感操作授权保持现有正式合同。

## 5. 正式接口并入

当前 3210 使用的认证、经营概览、客户、车辆、Business Order、维修轮次、Inspection Report、收付款、退款凭证、Receipt、业务文档、基础资料、停车、绩效、收入和附件接口全部改为同进程调用。

接口请求与响应格式保持兼容。动态路由参数按 Next.js 16 异步 Request API 规则处理。附件下载、表单上传、JSON 写入、Cookie 和错误状态不得因并入而改变。

下列运行依赖从唯一应用中移除：

- `FORMAL_BACKEND_ORIGIN`；
- 对 `127.0.0.1:3211` 或 `localhost:3211` 的服务端请求；
- 单独启动 3211 的开发、构建和生产入口。

## 6. 绩效目标计算

经营概览和绩效页面按正式 PostgreSQL 月度版本计算目标：

```text
成员携带目标（JMD） = 月标准工资（CNY） ÷ 工时费提成比例 × CNY→JMD 汇率
班组目标 = 当月归属该班组的成员携带目标之和
全店目标 = 各班组目标之和
完成率 = 当月有效正式交单绩效 ÷ 目标 × 100%
```

取值规则：

- 参数版本选择 `effective_month <= 统计月份` 的最近一版；
- 员工工资和班组归属同样选择统计月份可用的最近一版；
- 当月在职且有班组归属的员工进入目标计算；
- 金额在服务端以 minor unit 计算，最终目标四舍五入到 JMD 分；
- 完成率保留两位小数；目标为零时完成率为空。

如果无法计算，接口必须返回具体缺失项，例如“缺少 2026-08 绩效参数”或“维修一组：张三缺少月标准工资”。页面显示这些原因，不再用笼统提示代替诊断。

## 7. 性能

- 候选版本必须使用生产构建与 `next start` 做最终测速，避免开发编译时间混入结果。
- 经营概览、绩效和停车的首个业务请求不得经过第二个 Web 服务。
- 保持独立数据库查询并行执行，避免新增串行瀑布。
- 不为本次合并引入新的前端状态库或缓存层。

## 9. 验收门槛

候选版本必须同时满足：

1. `apps/web` 完成 Next.js 16 / React 19 类型检查、单元测试和生产构建；
2. 正式服务端全部现有测试通过；
3. 受保护页面未登录时进入登录页，正式账号可登录、刷新、注销并重新登录；
4. 经营概览、客户、车辆、Business Order、Inspection Report、收付款、停车、绩效和收入读取正式恢复数据；
5. 至少一条现有写入流程在隔离数据库中通过，并能在刷新后读回；
6. `/api/formal/*` 不产生对 3211 的网络请求，候选环境即使把旧后端地址设为不可达仍能完成核心流程；
7. 绩效参数完整时自动计算目标，参数缺失时页面显示具体缺失项；
8. 桌面浏览器中登录、经营概览、绩效和一条业务流程无框架错误层、无相关控制台错误；
9. 3210 与 3220 的关键页面截图不存在可见结构性差异；
10. 候选生产运行只有一个 Next.js 页面/API 监听端口。

任何一项失败，候选版本不替换当前 3210。

## 10. 切换与回退

本次工作先交付已验证的 3220 候选版本。用户确认候选界面后，切换动作只改变启动入口和端口：停止旧 3210/3211 Web 进程，使用当前正式数据库与附件目录启动单体应用到 3210，再重复登录、数据、写入、打印、测速和监听器检查。

切换失败时停止新进程并恢复原 3210/3211 启动方式。源码可回到切换前 Git SHA；数据和附件可使用冻结备份恢复。
