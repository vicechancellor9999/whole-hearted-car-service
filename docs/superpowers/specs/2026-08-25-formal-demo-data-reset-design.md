# 正式演示数据彻底清理设计

## 目标

3210 的客户、车辆、业务单、经营概览只读取正式 PostgreSQL 数据。删除旧 Mock 批量种子和浏览器残留造成的假关系，建立少量、可解释、可编辑、可计算的演示数据。

## 清理边界

- 允许删除：Mock 客户、车辆、业务单、收付款、停车、绩效 seed/fixture，以及浏览器中本项目的演示 localStorage/IndexedDB 数据。
- 正式本地数据库仅删除现有演示业务记录；保留唯一超级管理员账号、登录凭据和系统源码。
- 不删除 Git 历史、规格文档、用户文件、截图、上传文件目录或无关未提交改动。

## 正式车辆主档

正式车辆结构保存：正式车辆编号、车牌、CHASSIS NO.、发动机号、品牌中文、品牌英文、车型中文、车型英文、年份、颜色、车身类型、燃油、排量 CC、座位数、用途、特别说明、当前付款责任客户、启用状态和版本号。

不保存“版本/配置”和“动力类型”。车辆在场状态不允许手工填写，由维修轮次接单与取车事实派生。

## 页面规则

- 新建与编辑使用同一组正式字段，超级管理员和前台均能修改；老板视角只读。
- 详情页按“车辆身份、品牌车型、车辆参数”显示：年份单独显示；燃油与排量同组；座位数单独显示；车身类型、燃油、用途均为中文。
- 所有修改经过正式 API、乐观锁版本号和审计记录，不再写浏览器 Mock 数据。

## 演示基线

演示基线只保留能逐项解释的数据：

1. 一位个人客户和一台个人车辆。
2. 一家公司、一位从个人档案选择的联系人和一台公司车辆。
3. 收费单位“工时、件”。
4. 一张尚未派单的正式 Business Order，包含一条工时和一条配件收费、逐项折扣、分类折扣、整单折扣与备注。

在尚未建立维修班组和维修工账号时，不制造交单、绩效、应收、收款、退款或停车事实，因此经营概览必须显示这些值为零。

## 验收

- 刷新和重新登录后数据仍存在。
- 客户、车辆和 Business Order 可从列表进入、编辑后保存并立即回读。
- 业务单收费汇总能由明细重新计算一致。
- 页面不再出现 `UAT`、`BULK`、`Synthetic`、`DEMO 01`、英文枚举值或伪造附件。
- 浏览器控制台无错误，3210 与 3211 均为实际监听状态。
