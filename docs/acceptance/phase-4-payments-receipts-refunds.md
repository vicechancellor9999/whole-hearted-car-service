# 阶段 4：收款、Receipt 与退款验收清单

验收对象：Whole Hearted 正式系统，PC 网页端。

验收原则：必须使用真实本地 PostgreSQL 测试库和真实页面操作；自动测试通过不等同于人工验收通过。每一步记录角色、URL、输入、生成编号、页面结果和数据库结果。

## 一、验收前准备

- [ ] PostgreSQL 测试库已启动，`0014_payments_receipts_refunds.sql` 已完成迁移。
- [ ] 正式系统在 `http://127.0.0.1:3211` 启动，健康检查通过。
- [ ] 准备超级管理员、前台、老板只读三个账号。
- [ ] 至少有“现金”和一种非现金支付方式，且均处于启用状态。
- [ ] 准备一张已有收费项目的 Business Order，收费项目含工时、配件、其他费用、本项折扣、分类折扣、整单折扣和备注。
- [ ] 准备 JPG/PNG/WebP/PDF 格式的退款凭证和客户签字文件各一份，单文件小于 25 MB。

## 三、Receipt 内容与补打

- [ ] 分别打开三张 Receipt 的中文版。
- [ ] 核对 Receipt 显示 Business Order 全称和编号、客户、车辆、收费项目、工时/配件/其他费用、本项折扣、分类折扣、整单折扣、含税应收和所含 15% GCT。
- [ ] 核对 Receipt 显示出具时已有的历次收付款、本次收款、收款方式、时间和收款后余额。
- [ ] 核对责任义务和提前告知备注完整显示。
- [ ] 切换英文版，核对英文项目名称、描述、单位、备注和标题。
- [ ] 点击打印，确认 A4 页面不显示系统导航和操作按钮。
- [ ] 修改 Business Order 当前收费项目，再补打第一张 Receipt。
- [ ] 确认第一张 Receipt 的编号、收费快照、历史和余额仍为最初出具时内容，没有按新收费重算。

## 四、退款权限与自由金额

- [ ] 取消前台的敏感操作下放权限。
- [ ] 以前台打开退款区域，确认没有退款按钮或提交时被拒绝，且数据库没有新增退款事实。
- [ ] 由超级管理员向前台下放 `sensitive_operations.execute`。
- [ ] 前台刷新页面后出现退款入口。
- [ ] 输入任意退款金额，不选择任何收费项目，确认页面本身没有退款项目选择器。
- [ ] 使用非现金方式、填写原因、选择原单已交回并上传退款凭证后提交。
- [ ] 确认新增一条独立退款记录；原收费项目、收款、Receipt、正式交单和绩效均未被修改。

## 五、现金签字与原单无法交回

- [ ] 选择现金退款但不上传客户签字，确认系统拒绝且没有新增退款事实。
- [ ] 上传退款凭证和客户签字后重新提交，确认成功。
- [ ] 选择“原单无法交回”但不填说明，确认系统拒绝。
- [ ] 填写原单无法交回说明后提交，确认成功。
- [ ] 打开“退款说明与客户签收单”，确认车辆、Business Order、退款金额、时间、方式、原因、原单情况、退款凭证和客户签字集中在同一张单，不拆成多张单据。
- [ ] 点击打印，确认 A4 打印页不显示系统导航和操作按钮。

## 六、金额守恒与不可修改事实

- [ ] 页面满足：`未结余额 = 当前折后应收 - 累计收款 + 累计退款`。
- [ ] 退款金额大于此前收款时仍可记录，余额按事实公式增加，系统不替用户决定抵扣项目。
- [ ] 尝试直接修改或删除收款、Receipt、退款、退款证据，确认数据库拒绝。
- [ ] 核对每笔 Receipt 只属于一笔收款，每笔收款只有一个 Receipt。
- [ ] 核对补打不产生新 Receipt 编号。

## 七、老板只读与审计

- [ ] 以老板账号打开同一 Business Order，确认可查看应收、累计收款、累计退款、余额、每笔历史和单据。
- [ ] 确认老板页面没有收款和退款入口。
- [ ] 检查审计记录包含每笔 `payment.recorded`。
- [ ] 检查每笔退款包含 `refund.created`，并记录车辆所属 Business Order、操作人、退款原因、金额、方式、原单情况和证据类型。
- [ ] 确认后续日报数据源能把退款列入具体敏感操作明细，但日报净收款只显示一个结果金额。
